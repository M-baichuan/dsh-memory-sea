# DSH-Memory-Sea 说明书

面向使用者的完整操作说明：从环境准备、配置、启动，到记忆海、人设与日常运维。

若你用的是 **DeepSeek Harness 桌面端**（不是浏览器 Web），请先看：  
**[桌面端说明书.md](./桌面端说明书.md)**

若之前已经在跑 **SnowLuma + qq-bridge + Magpie/workbuddy**，再看：  
**[从旧qq-bridge迁移说明书.md](./从旧qq-bridge迁移说明书.md)**

---

## 1. 这是什么

**DSH-Memory-Sea** 是一套跑在本机的 QQ 鲸鱼娘陪伴机器人：

| 部件 | 作用 |
|---|---|
| SnowLuma / NapCat | 把个人 QQ 号变成 OneBot v11 通道 |
| `packages/bridge` | QQ 消息 ↔ DeepSeek Harness 的桥 |
| DeepSeek Harness (DSH) | 真正跑 Agent / 模型的宿主 |
| 记忆海 `memory-sea` | 长期记忆：会记住、会召回、也会按艾宾浩斯曲线逐渐遗忘 |
| 鲸鱼娘人设 | 说话风格与行为边界（Markdown，可改） |

一句话：**QQ 只是入口；线那头是 DSH 里的她，背后有一片会潮起潮落的记忆海。**

> 个人号 + 非官方协议端有风控风险。请用小号，遵守 QQ 用户协议与当地法律。安全细则见仓库根目录 [RULES.md](../RULES.md)。

## 2. 运行前需要准备

| 依赖 | 要求 |
|---|---|
| 系统 | Windows 10/11（脚本按 Windows 写了；核心代码跨平台） |
| Node.js | **≥ 22**（使用内置 `node:sqlite`） |
| 包管理 | pnpm（可用 `npm i -g pnpm`） |
| DeepSeek Harness | 本机 **桌面端**（profile=`desktop`；也可用 web，但默认按桌面端写） |
| QQ 协议端 | SnowLuma（推荐）或 NapCat，暴露 OneBot v11 |
| QQ 号 | **建议小号** |

默认端口约定：

| 服务 | 地址 |
|---|---|
| OneBot WebSocket | `ws://127.0.0.1:3001` |
| OneBot HTTP | `http://127.0.0.1:3000` |
| DSH Desktop Host | 随机本机端口（可用 `pnpm discover:dsh` 探测；可固定如 `43189`） |
| Memory Sea 控制台 | `http://127.0.0.1:3120` |

若你的端口不同，在 `config.json` 里改即可。

## 3. 安装项目

在仓库根目录（`D:\memory_sea_project` 或你的克隆路径）执行：

```powershell
pnpm install
pnpm build
Copy-Item config.example.json config.json
```

然后用编辑器打开 **`config.json`**，至少填下面这些字段。

### 3.1 从旧 qq-bridge 迁过来（你已有配置时）

旧桥目录例如 `D:\path\to\qq-bridge`，对照迁移：

| 旧字段 | 新字段 |
|---|---|
| `snowluma.wsUrl` / `httpUrl` / `accessToken` | `onebot.*` |
| `dsh.baseUrl`（注意桌面端端口可能是动态的） | `dsh.baseUrl` |
| `ownerQQ` + `allow.private` | `access.admins` + `access.allowUsers`（写成字符串） |
| `allow.groups` | `access.allowGroups` |
| 触发关键词 | `access.triggerNames` |

**模型（Magpie / workbuddy）怎么处理：**

1. 新配置保持 `lockModel: false`，`model` / `provider` 留空  
2. **先停掉旧 qq-bridge**（它会强行 `selectModel` 成官方 flash）  
3. 打开 DSH Web，手动选你在 Magpie/workbuddy 里要用的模型  
4. 再启动本仓库的 `pnpm bridge`  

不要把旧配置里的 `deepseek-v4.1-flash` + `workbuddy` 直接写进新配置并开 `lockModel`，除非你确认这个组合就是你现在要用的、且不会被桥接反复覆盖。

**不要删：** `D:\SnowLuma`（协议端继续用）  
**不要同时跑：** 旧 qq-bridge 与本仓库 bridge  
**旧 qq-bridge 目录：** 可留作备份，稳定后再删

## 4. 配置说明（`config.json`）

### 4.1 OneBot（必填）

```json
"onebot": {
  "wsUrl": "ws://127.0.0.1:3001",
  "httpUrl": "http://127.0.0.1:3000",
  "accessToken": "与协议端一致的 token",
  "selfId": "机器人自己的 QQ 号"
}
```

- `accessToken` 必须与 SnowLuma / NapCat 里配置的一致；没有 token 可留空，但不推荐。
- `selfId` 用于识别群里是否 @ 到自己。

协议端示例见 [deploy/snowluma.example.yml](../deploy/snowluma.example.yml)。

### 4.2 DSH

```json
"dsh": {
  "baseUrl": "http://127.0.0.1:43189",
  "profile": "desktop",
  "model": "",
  "provider": "",
  "lockModel": false,
  "workspaceGroup": "QQ 聊天"
}
```

确认 **DeepSeek Harness 桌面端**已启动。桌面端端口常会变，用 `pnpm discover:dsh` 核对后写入 `baseUrl`。详细见 [桌面端说明书.md](./桌面端说明书.md)。

**Magpie / 自定义反代注意（重要）**

旧 qq-bridge 有个坑：启动后会对会话调用 `session.selectModel`，默认钉死官方 `deepseek-flash`（DeepSeek-V4.1-Flash），还会写进 DSH 全局默认，于是你在 Magpie 里选好的模型每次被切回去。

本项目默认：

- `lockModel: false` → **不强制改模型**，沿用 DSH / Magpie 当前选择
- 只有你显式设 `lockModel: true` 且填写 `model`（以及可选 `provider`）时，才会在**新建** QQ 会话时带上该模型
- 不会在每条消息、每次启动时反复 `selectModel` 覆盖全局

若必须锁定某个 Magpie 模型，写成 Magpie 侧真实的 model id / provider id，例如：

```json
"dsh": {
  "lockModel": true,
  "provider": "magpie",
  "model": "你在 Magpie 里看到的模型 id"
}
```

### 4.3 访问控制（强烈建议配置）

```json
"access": {
  "admins": ["你的QQ号"],
  "allowUsers": ["允许私聊的QQ号"],
  "allowGroups": ["允许的群号"],
  "requireMention": true,
  "triggerNames": ["鲸鱼娘", "鲸鲸"]
}
```

行为规则：

1. **管理员**（`admins`）始终放行。
2. 若 `allowUsers` / `allowGroups` **非空**：名单外私聊/群聊会被拒绝，并回复一句「待批准」。
3. 若两边都 **为空**：相当于开放（仍受群触发规则约束）——仅适合本机调试。
4. 群聊且 `requireMention=true` 时：需要 **@ 机器人**，或消息里出现 `triggerNames` 里的名字，才会进模型。

### 4.4 记忆海

```json
"memory": {
  "dbPath": "data/memory/sea.sqlite",
  "injectCharLimit": 600,
  "recallLimit": 6,
  "pruneThreshold": 0.05
}
```

| 字段 | 含义 |
|---|---|
| `dbPath` | sqlite 文件路径（相对仓库根） |
| `injectCharLimit` | 每回合自动注入记忆块的字符上限 |
| `recallLimit` | 每回合最多召回几条 |
| `pruneThreshold` | strength 低于该值时，夜间维护会剪掉 |
| `categories.*.baseLambda` | 各类记忆的衰减速度；越大忘得越快 |

记忆分类默认：`identity`（身份）忘得最慢，`chat_noise`（闲聊）忘得最快。公式与细节见 [memory-model.md](./memory-model.md)。

### 4.5 桥接与控制台

```json
"bridge": {
  "textChunkLimit": 400,
  "consoleToken": "自己设一个随机串",
  "consolePort": 3120
}
```

- `textChunkLimit`：发回 QQ 时单条字数上限，超长自动分句。
- `consoleToken`：打开控制台 API 时放在请求头 `x-console-token`；**建议设置**。

### 4.6 人设

```json
"persona": {
  "id": "whale",
  "contentDir": "packages/persona/content/whale"
}
```

改人设只需编辑该目录下三个文件后重启 bridge：

| 文件 | 内容 |
|---|---|
| `SOUL.md` | 她是谁、怎么相处 |
| `STYLE.md` | 说话风格 |
| `BOUNDARIES.md` | 不该记什么、不该做什么 |

**改人设不会清空记忆库。**

### 4.7 QQ 空间动态（草稿确认）

不会自动发说说。管理员在 QQ 里：

| 指令 | 作用 |
|---|---|
| `选择发动态类型` / `/动态类型` | 列出类型（心情/日常/想念/吐槽/晚安/早安/随想） |
| `/动态类型 心情` / `选择发动态类型 2` | 按类型生成草稿 |
| `发条动态` / `/动态` | 生成草稿；可写 `发条动态 日常 下雨天` |
| `确认发动态` / `发布动态` | 真的发到 QQ 空间 |
| `取消动态` | 丢掉草稿 |
| `看看草稿` | 查看未发草稿 |

配置（`social.qzone`）：

```json
"qzone": {
  "enabled": true,
  "ugcRight": 4
}
```

- `ugcRight`：`1` 所有人 · `4` 好友（默认）· `64` 仅自己  
- 依赖协议端 **NapCat** 的 `send_qzone_msg`；失败时草稿仍保留，可再确认。  
- 更短说明：`docs/记忆海-空间动态说明.txt`

### 4.8 社交技能

QQ 里发 `技能` 可看菜单。详见 `docs/记忆海-技能说明.txt`。

| 技能 | 例句 |
|---|---|
| 小约定 | `约定 30分钟后 喝水` / `看看约定` |
| 悄悄话 | 群里 `悄悄话：今天有点累`（只私聊回） |
| 表情导演 | `配个表情 无语` |
| 回看切片 | `回看 上周烦的事` |
| 口味地图 | `口味地图` / `我喜欢 火锅` |
| 知识库 | `知识入库`（管理员）/ `知识搜 关键词`；详见 `docs/记忆海-知识库说明.txt` |
| 自主 | `自主状态` / `闭嘴` / `开口`；详见 `docs/记忆海-自主说明.txt` |

开关：`social.skills.*`（默认全开）。自主另见 `social.autonomy.enabled`。

## 5. 启动顺序（推荐）

按这个顺序开，少踩坑：

```text
1) 启动 SnowLuma / NapCat，确认 QQ 已登录、OneBot WS 可连
2) 启动 DeepSeek Harness 桌面端，并在桌面端选好 Magpie 模型
3) pnpm discover:dsh → 把端口写入 config.json
4) （首次）安装 DSH 插件到 desktop profile
5) 启动 bridge
6) （可选）启动控制台
```

### 5.1 安装 DSH 插件（首次，桌面端）

先完整打开一次桌面端，再**完全退出**，然后：

```powershell
pnpm setup:plugins
```

默认装到 profile **`desktop`**。若要用 web：

```powershell
$env:DSH_PROFILE="web"
pnpm setup:plugins
```

装的是：

- `@dsh-memory-sea/memory-tools` — 给 Agent 的 `memory_recall` / `memory_save` / `memory_search`
- `@dsh-memory-sea/whale-preset` — 鲸鱼娘 preset

装完后**重启 DSH**。手工 patch 示例见 [deploy/dsh-profile.patch.example.yml](../deploy/dsh-profile.patch.example.yml)。

> 若本机还没有 `dsh` CLI，`setup:plugins` 可能提示失败；可先只跑 bridge——此时模型侧会走本地回退文案，方便你先验证 QQ 收发与记忆注入链路。

### 5.2 启动桥接

```powershell
pnpm bridge
```

或一键脚本：

```powershell
.\deploy\windows\start-all.ps1
```

看到类似日志即成功：

```text
[bridge] started
[bridge] OneBot connected ws://127.0.0.1:3001
```

### 5.3 启动控制台（可选）

另开一个终端：

```powershell
pnpm console
```

浏览器打开：`http://127.0.0.1:3120`

可做：

- 按 scope / channel 召回（验证群聊不会漏出 private）
- 查看 pending、钉住 / 改 visibility
- 刷新「星海图」（本机 canvas，无外挂服务）
- 手动跑一次维护

## 6. 怎么跟她聊天

### 私聊

1. 用已在 `allowUsers`（或管理员）里的号发消息。
2. bridge 会：准入 → 自动抽取简单事实 → 召回记忆 → 交给 DSH → 把回复发回 QQ。
3. 若 DSH 暂时不可用，会收到带「本地回退」提示的回复（QQ 链路仍通）。

### 群聊

1. 群号在 `allowGroups`（或管理员）。
2. 默认需要 **@ 她**，或喊触发名（如「鲸鱼娘」「鲸鲸」）。
3. 每个群有独立 DSH 会话，不会和别的群串上下文。

### 记忆会怎么进库

- **规则抽取**：识别「我叫 / 我喜欢 / 我住在 / 我养了…」一类句子，自动尝试入库。
- **模型工具**：DSH 里挂了 memory-tools 后，她可以主动 `memory_save` / `memory_search` / `memory_pin`。
- **场合隔离（来自记忆星海思路）**：
  - 私聊记下的偏好默认 `private`，**群里召不回**
  - 群聊约定默认 `group`，只在该群可见
  - 需要两边都能用的事实可标 `public`
- **钉住**：重要底色可用 `memory_pin`；钉住的记忆夜巡不剪掉
- **质量闸门**：
  - 像密码、验证码、银行卡等敏感内容 → **拒绝写入**
  - 置信度偏低 → 进入 **pending（待核实）**，不自动注入对话
  - 近重复内容 → 合并更新，不无限堆叠
  - 同 `factKey` 的新事实会归档旧条（冲突取代）

### 记忆作用域（避免串记）

| Scope | 含义 | 例子 |
|---|---|---|
| `user:<QQ号>` | 这个人的跨群事实 | 名字、喜好 |
| `group:<群号>` | 群约定 / 群事件 | 「周五团建」 |
| `relation:<QQ>@<群号>` | 此人在该群里的关系侧写 | 群内称呼、相处方式 |

私聊召回只看 `user`；群聊会同时看三级。

## 7. 日常运维

### 7.1 夜间维护（巩固 / 遗忘 / 剪枝）

```powershell
pnpm maintenance
```

或计划任务跑：

```powershell
.\deploy\windows\nightly-memory.ps1
```

它会：

1. 按艾宾浩斯 strength 剪掉过弱记忆（`pruned`）
2. 合并近重复记忆（`consolidated` / `archived`）

建议每天凌晨跑一次。输出示例：

```json
{
  "ok": true,
  "dbPath": "D:\\memory_sea_project\\data\\memory\\sea.sqlite",
  "pruned": 2,
  "consolidated": 1,
  "archived": 1
}
```

### 7.2 自检

```powershell
pnpm build
pnpm test
pnpm smoke
```

`smoke` 会在临时库里写入一条记忆并验证「召回注入」是否正常。

### 7.3 数据在哪

| 路径 | 内容 | 是否入库 |
|---|---|---|
| `config.json` | 你的真实配置 | 否 |
| `data/memory/sea.sqlite` | 记忆海数据库 | 否 |
| `data/state/sessions.json` | QQ 对话 ↔ DSH 会话映射 | 否 |
| `data/keys/` | 预留密钥目录 | 否 |

备份记忆：复制 `data/memory/sea.sqlite`（停写或停 bridge 时更稳妥）。

### 7.4 改代码后

```powershell
pnpm build
# 再重启 bridge / console
```

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| bridge 一直重连 OneBot | 协议端没开 / 端口或 token 不对 | 检查 SnowLuma、`wsUrl`、`accessToken` |
| 私聊没反应 | 不在白名单 | 把 QQ 号写入 `allowUsers` 或 `admins` |
| 群里不回话 | 没 @、没喊名字 | @ 机器人，或说触发名；或临时设 `requireMention: false` |
| 回复是「DSH 暂不可用」 | DSH 没开或插件 API 未就绪 | 启动 DSH；执行 `pnpm setup:plugins` 后重启 DSH |
| 她不记得昨天的事 | 没召中 / 已衰减 / 在 pending | 控制台查 pending；确认 `pnpm maintenance` 没误剪；提高 importance |
| 控制台 401 | token 不对 | `config.bridge.consoleToken` 与页面里填写一致 |
| `node:sqlite` 报错 | Node 版本过低 | 升级到 Node 22+ |

日志：bridge 在终端输出；会话映射见 `data/state/sessions.json`。

## 11. V1 明确不做的事

- 不接官方 QQ 开放平台 Bot API（当前是个人号 OneBot）
- 不做完整「90 工具 / 大型管理后台」
- 向量检索留给后续版本（当前：关键词 + strength）

先打通的目标是：**能聊、能记、会忘。**

## 12. 最小验收清单

装好并配置后，按这个勾一遍：

1. [ ] `pnpm build` 成功  
2. [ ] `pnpm smoke` 输出 `"ok": true`  
3. [ ] SnowLuma 在线，bridge 显示 OneBot connected  
4. [ ] DSH web 可打开  
5. [ ] 管理员私聊一句话，能收到回复  
6. [ ] 对她说「我叫某某」，下一句问名字时，回复或注入块里能看到相关记忆  
7. [ ] `pnpm maintenance` 能正常跑完  

全部打勾，就可以日常用了。
