# DeepSeek Harness 桌面端说明书

本仓库默认按 **DSH Desktop（桌面端）** 使用，不是浏览器里的 `dsh web`。

典型桌面端情况：

- Profile：`~/.dsh/profiles/desktop`
- 若使用 Magpie，模型 id 以桌面端设置为准（例如 `magpie` + `workbuddy/...`）
- 桌面端本地 API 端口多为**随机分配**，可用 `pnpm discover:dsh` 探测

---

## 1. 和 Web 版差在哪

| | Web (`dsh web`) | Desktop（你现在用的） |
|---|---|---|
| 怎么开 | 命令行 / 浏览器 | DeepSeek Harness 桌面应用 |
| Profile 名 | `web` | **`desktop`** |
| 本地端口 | 常固定 `3080` | **默认随机**，每次启动可能变 |
| 装插件 | `dsh plugin --profile web add …` | `dsh plugin --profile desktop add …` |
| 模型 | 在 Web 设置里选 | 在**桌面端窗口**里选；也可写在 `profiles/desktop/cordis.patch.yml` |

桥接连的是桌面端在本机开的 HTTP Host，不是「再开一个 Web」。

---

## 2. 配置（`config.json`）

关键三项：

```json
"dsh": {
  "baseUrl": "http://127.0.0.1:你的桌面端端口",
  "profile": "desktop",
  "model": "",
  "provider": "",
  "lockModel": false,
  "workspaceGroup": "QQ 聊天"
}
```

### 2.1 怎么查当前桌面端端口

任选一种：

1. **看旧桥配置里的 `dsh.baseUrl`**（仅作参考；重启后端口常会变）。

2. **本仓库探测脚本**（桌面端先开着）：

```powershell
cd D:\your_project
pnpm discover:dsh
```

优先看返回里 **status=401** 的地址（桌面端要鉴权）；**不要**用 Magpie 网关的 `3425`。  
把 `recommendedBaseUrl` 填进 `dsh.baseUrl`，然后重启 bridge。

3. **固定端口（推荐，省得每次改）**  
   在桌面端设置 / profile patch 里固定，例如：

```yaml
dsh-desktop:
  port: 43189
```

然后 `config.json` 长期写：

```json
"baseUrl": "http://127.0.0.1:43189"
```

改完后完整退出并重开桌面端。

### 2.2 模型（Magpie）怎么处理

本仓库默认保持：

- `lockModel: false`
- `model` / `provider` 留空  

→ **桥接不会改模型**，继续用桌面端 / Magpie 当前选择。

不要把官方 `deepseek-flash` 写进本仓库并开 `lockModel`，否则会重演旧 qq-bridge 的切模型问题。

若你想让本桥在新建 QQ 会话时也显式钉 Magpie 模型（一般没必要）：

```json
"dsh": {
  "lockModel": true,
  "provider": "magpie",
  "model": "你在桌面端看到的完整模型 id"
}
```

id 必须与桌面端里完全一致。

## 3. 给桌面端装记忆插件

1. **先完整打开一次桌面端**（初始化 `desktop` profile）  
2. **完全退出**桌面端（托盘也退出）  
3. 在本仓库执行：

```powershell
cd D:\your_project
pnpm setup:plugins
```

默认已改为装到 **`desktop`**。等价于：

```powershell
dsh plugin --profile desktop add .\plugins\memory-tools
dsh plugin --profile desktop add .\plugins\whale-preset
```

若系统里的 `dsh` 不是桌面端自带的 CLI，请用**桌面端托盘打开的终端**再执行上面两条，或把桌面端安装目录里的 `dsh.cmd` 加入 PATH。

4. 再打开桌面端。

## 4. 日常启动顺序（桌面端用户）

```text
1) SnowLuma（QQ 协议端）
2) Magpie（若反代要单独开）
3) DeepSeek Harness 桌面端 —— 确认模型仍是 Magpie 那条
4) 核对 / 更新 config.json 的 dsh.baseUrl（端口变了就改）
5) pnpm bridge
6) （可选）pnpm console
```

**务必先停掉旧 qq-bridge**，再开本仓库 bridge。

## 5. 桌面端 Host cookie 鉴权（重要）

桌面端 Host **会拦没有 cookie 的请求**（常见 401）。  
本仓库默认走 **方案 B**：bridge 用本机 `~/.dsh/.credentials.yaml` 里的
`client-connection/browser-session` 密钥，**自动铸造**与 qq-bridge 同款的会话 Cookie。

配置：

```json
"dsh": {
  "autoMintCookie": true,
  "cookie": ""
}
```

启动日志应出现类似：

```text
[bridge] DSH Host auth ready (minted) → http://127.0.0.1:xxxxx
[bridge] DSH health ok status=200
```

弹窗若问「bridge 被 Host cookie 鉴权挡住」→ 选 **方案B**（给 bridge 补 cookie，继续用现桌面端）。  
本仓库已实现自动铸造，提交方案B后重启 `pnpm bridge` 即可。

若仍是 401：

1. 确认桌面端已打开，且 `dsh.baseUrl` 端口就是当前这次启动的端口（弹窗里的端口，如 `57913`；`pnpm discover:dsh` 里带 401 的那个，再以 health/RPC 复核）
2. 确认存在 `~/.dsh/.credentials.yaml`，且桌面端至少成功启动过一次
3. 一般**不必**手动填 cookie；只有自动铸造失败时才把浏览器里 Host 下发的 cookie 填进 `dsh.cookie`

**不要选「改用 dsh web」**，除非你明确想离开桌面端。

## 6. 验收

1. [ ] 桌面端已打开，不是 `dsh web`  
2. [ ] `pnpm discover:dsh` 端口与 `config.json` 一致  
3. [ ] bridge 日志有 `DSH Host auth ready` 且 health ok  
4. [ ] 桌面端模型仍是你选的 Magpie / 自定义供应商模型  
5. [ ] `pnpm bridge` 显示 OneBot connected  
6. [ ] 私聊/群触发能回消息  

若回复是「DSH 暂不可用」或 cookie 鉴权失败：先查端口与 `autoMintCookie`，再查插件是否装进 `desktop` profile。
